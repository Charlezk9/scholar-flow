# 日历重复事件施工图

2026-11-11。对应 PRD `EV-14`、`EV-15`；状态只维护于 PRD §5.0。文件名中的 v1.x 仅沿用计划命名约定，不指定发布版本。本轮交付为进度核查与规划，不实施功能或发布应用。

## 1. 用户确认的目标

日历事件只设置一次，即可每周固定时间参加组会，或在以后年份显示生日。需求与验收标准见 PRD §5.3。旧 `EV-08~EV-11` 已作废，本轮使用新编号，不复用旧重复事件编号。

以下数据结构与顺序为工程方案；待确认项不作为新增需求。每日、每月、自定义间隔、通知、第三方同步和完整 RRULE 编辑器均不因本次规划加入范围。

## 3. 推荐技术路线

保留 SQLite 中的一条主事件，前端领域层按可见区间生成只读显示实例，不预先复制未来年份的数据库记录。复用现有 API 与状态管理，新增独立纯函数模块处理重复日期，便于直接测试。

1. **主数据与实例分离**：建议显示实例携带 seriesId、occurrenceDate、instanceKey（系列 ID + 本次日期），其起止日期用于布局；编辑时查回主记录，不能将显示日期覆盖为系列起始日期。单次事件沿用原有行为。
2. **规则契约**：优先复用 repeatRule 字符串，约定有版本、可校验的最小格式；只编码已确认的每周和每年规则。每周锚定首次日期的星期，保持本地钟面时间及事件时长，不用固定毫秒数跨日期累加。每年历法在确认后定格式。repeatUntil 继续兼容，不因字段存在添加结束日期控件。
3. **查询与展开**：状态层缓存主事件，独立 selector 按月网格、周或日区间展开。事件读取需保证取得起始日期早于当前窗口的重复主记录；现有 1900–2200 查询仅是现状限制，不能据此宣称支持任意年份。对跨日实例按区间相交判断，包含窗口开始前发生、窗口内仍持续的实例。按日期计算首个候选，避免从系列起点逐日扫描。
4. **统一消费**：MonthView、WeekView（日视图复用）、DayPopover 共同消费实例；继续使用现有布局函数。实例键负责渲染，主事件 ID 负责持久化。跨月/跨年导航重算实例，不重复写数据库。
5. **表单与动作**：在现有事件抽屉增加重复设置，复用自绘控件和日期/时间选择器。表单显示清晰的每周/每年摘要。修改、删除、移动、复制的作用范围确认后再接线，保存失败不得误报成功。浮层 Portal 到 body，保持字号缩放与明确的收缩关系。
6. **兼容与备份**：规则为空仍为原单次事件；不能静默将未知旧规则解释成新规则。Rust 保存入口校验允许的格式，与浏览器模拟后端保持一致。若最终方案需要新增字段或表，先备份再迁移；仅复用已有字段时不为形式升级数据库版本。

## 4. 待确认项与推荐值

以下是决策入口，不登记为已确认需求；可以先完成独立的每周展开逻辑设计，涉及这些选择的实现须等待明确。

| 决策 | 推荐值及理由 |
| --- | --- |
| 生日历法 | 待用户选择公历、农历或两者；不可用已有农历显示能力推断生日一定按农历重复 |
| 修改、删除重复事件的范围 | 首次实现建议整组生效，并在操作前明确提示；「仅本次」「本次及以后」需要例外或拆分模型，待用户确认后再立项 |
| 2 月 29 日及农历特殊日期 | 公历建议仅在有该日期的年份出现；若需要农历，应另明确闰月生日和缺少对应日期的处理，不擅自顺延 |
| 复制与移动的含义 | 复制建议沿用现有行为，只复制当前一次为独立事件；移动建议与整组编辑采用相同范围语义，避免同一事件入口行为矛盾 |

## 5. 实施顺序与验证门槛

1. **定规则与身份契约**：明确上述决策后补充 PRD 的相应验收；确定主记录、实例以及保存输入的边界。

3. **接入抽屉及各视图**：贯通新建、重开、切换月份/年份；处理实例点击及已确认范围的修改删除行为。
