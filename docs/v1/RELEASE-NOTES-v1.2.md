## 2. 为什么要重定义

原来「议程」是「未来 120 天逐日列出有内容的日期」——和月/周/日视图**看的是同一批对象**，只是换了个粒度。
而真正的空缺是另一类东西：**「有件事要做，但还没决定哪天做」**。

这类东西以前只能硬塞进日历（随便挑一天，结果日历变脏），或者塞进倒计时（但它没有目标时刻）——
两种塞法都在污染各自的数据语义。v1.2 给它一个自己的位置，并钉死边界：

| 对象 | 触发物 | 落点 |
| --- | --- | --- |
| 倒计时 | 一个不可移动的目标时刻 | 左栏 + 皇冠栏 |
| 日历事件 | 一个时间安排（已决定哪天/几点） | 日历格 |
| **议程事项**（新） | 一件要推进的事（**还没决定哪天**） | 议程页 |

## 3. 新增：议程页（`AG-01` ~ `AG-06`）

### 3.1 页面

- 顶栏从两个页面变三个：**日历 / 议程 / 设置**（视图分段相应收回成 `月 / 周 / 日` 三档）。
- **窄列 720px 居中**：待办是「读 + 勾」的场景，横跨整窗会很难扫（与日历页的宽布局形成分工）。
- 顶部常驻快速添加行：写标题 → `Enter` → 连续录入。
- 卡片**复用**倒计时卡片的全套视觉语言（底/描边/圆角/阴影/标题档位），不引入第二套样式。

### 3.2 事项与子项

- 事项 = 标题（可双击就地改名）+ 若干子项 + 可选置顶。
- 子项**与倒计时里程碑同形**（`title / done / done_at / sort_order`），
  并且 v1.2 把渲染与交互抽成了通用 `Checklist` —— 里程碑与议程子项**共用同一份实现**，
  而不是各写一套（否则以后修一个动效要改两处）。
- 折叠徽章 `☑ 2/5`、全部完成 `✓ 5/5`、`Enter` 连续添加、`Esc` 取消、`isComposing` 防误提交、
  点勾不会顺手折叠卡片（都是 v1.1 踩过坑之后固化下来的行为）。
- **事项本身没有「完成」状态**：完成度完全由子项表达，避免「父已完成、子项还有三个没做」这种自相矛盾。

### 3.3 ⋯ 菜单（卡片右上角仍然只留一个入口）

编辑标题 / 置顶 / **安排到某天…** / 复制一份 / 标记为已完成 / 删除。
已置顶时菜单项带朱砂状态色（`is-active`）——沿用 v1.1 `UI-24` 的规矩。

### 3.4 「安排到某天」——与日历的桥（`AG-05`）

```
⋯ →「安排到某天…」→ 站内浮层选日期 → 一个事务里：
    ① 创建全天事件（标题 = 事项标题，备注 = 事项备注 + 未完成子项清单）
    ② 事项移入已完成
→ Toast：「已安排到 10 月 12 日 ·「xxx」移入已完成」
```

- **单向出口**：事项出池后不再与事件保持关联 → 不存在「删了事件但标记还在」这类双向同步 bug。
- 未完成子项会写进事件备注，落地那天打开事件就能看到要做什么。
- 用站内浮层而不是原生弹窗（`UI-07`：wry 没实现 `window.prompt/confirm`，会静默失败）。

### 3.5 「接下来 7 天」（`AG-06`，可用 `SET-13` 关掉）

原来的「逐日时间轴列表」收成议程页顶部一个只读区块，点日期可跳到日历对应那天 ——
保住「一眼看到这周定了什么」的视角，同时不再和月/周/日视图重复。

## 4. 数据与迁移

```sql
CREATE TABLE agenda_items   (id, title, note, pinned, archived, sort_order, created_at, updated_at);
CREATE TABLE agenda_subitems(id, item_id → agenda_items(id) ON DELETE CASCADE,
                             title, done, done_at, sort_order, created_at, updated_at);
```

- 删除事项由外键级联清理子项（`PRAGMA foreign_keys=ON` 在 v1.1 已启用并有测试覆盖）。
- 首次升级（检测到还没有 `agenda_items` 表）会**先自动导出一份 JSON 兜底**，再建表；
  重复启动不会重复备份。
- 备份升到 `version: 3`，新增 `agendaItems` / `agendaSubitems`；老备份（v1/v2）语义等价于「没有议程数据」。
- 老库里的设置 `defaultView: "agenda"`（议程曾是视图）会在启动时**归一到 `month`**，
  避免打开就看见一块空白日历区。

## 7. 已知限制

- 议程事项**没有日期、没有提醒、没有优先级、没有标签** —— 这是刻意的（加了就重新变成半个日历）。
- 子项只有一层（不做无限嵌套）；不支持拖拽排序（按添加顺序）。
- 「安排到某天」目前只生成**全天事件**；想指定时刻就在日历里再编辑一下。
- 不做反向的「日历事件 → 转为待办」。
