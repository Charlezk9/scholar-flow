## 1. 目标与功能边界

1. **议程与日历是相互独立的功能页面**：议程管理无日期的事项和文字便签；日历管理某一天的日常安排与事件。
2. **议程采用两列排版**，提升纸面利用率与阅读层次。
3. **议程事项是一张便签**：标题下可添加待办项或一段文字，添加入口明确可见，补充纸张层次与适度动效。
4. **日视图增加日常安排栏**：默认四个空时间块，左侧日常安排、右侧事件，共用时间轴，内容分别管理。

术语统一：页面仍叫「议程」，其中的对象叫「议程事项／便签」；带日期的对象叫「日历事件」；每日类别安排叫「日常时间块」。避免三类对象都被叫作“事件”。

| 对象 | 日期与时间 | 内容 | 显示位置 |
| --- | --- | --- | --- |
| 议程事项 | 无日期 | 标题、文字、待办项 | 议程页面 |
| 日常时间块 | 本地日期 + 固定时段 | 一个类别 | 日历日视图左栏 |
| 日历事件 | 日期、全天或具体时段 | 标题、地点、备注等 | 月／周视图及日视图右栏 |

“时间块和事件不重叠”的已确认解释：**两类卡片在不同栏内显示，不发生视觉覆盖；可以占用相同钟点**。例如 09:00 的英语安排与 09:00 的会议并排可见。不增加跨栏时间冲突限制。

## 3. 议程页面设计

### 3.1 独立页面

- 顶栏保持「日历／议程／设置」，议程不是日历的视图选项。
- 议程不使用日历当前选中日期；日历切换日期不会改变便签内容、排序或展开状态。
- 切换页面时分别保留滚动位置；未保存编辑须保留草稿或明确提示处理，不能静默丢失。
- 移除议程中的「接下来 7 天」，保留「安排到某天」作为用户主动触发的单向出口：创建全天事件（正文 + 未完成待办写入备注），成功后事项移入已完成。事务失败不创建半条事件、不归档事项。
- 独立性指页面、日常操作与数据管理各自独立；显式安排操作不建立持续同步关系。旧日历事件与旧归档事项保留，不回写、不反向迁移。
- 对应设置 `showAgendaUpcoming` 停止提供入口；旧设置可保留兼容读取，不再影响 UI。

### 3.2 两列便签板

推荐页面内容最大宽度 1120px，左右内边距 24px，列间距 20px。页面标题、说明、快速添加和已完成折叠入口横跨两列。

- 使用普通两列 Grid，按**左→右、上→下**阅读；置顶→原有顺序的排序规则保持。
- 每张卡片按内容自然增高，同行另一张不拉伸；允许行底留白。首版不用瀑布流，保证视觉顺序、DOM 顺序和键盘顺序一致。
- 推荐可用内容宽低于 760px 时退为单列；应用支持的正常窗口宽度默认两列。字号特大也需验证，断点属于待实测的设计值。
- 新建便签只让新增卡片出现入场反馈，不让整个列表反复播放动画。置顶变化引起正常重排，焦点随原卡片保留。
- 已完成区展开后同样两列；无日期便签不会进入日历格。

### 3.3 便签结构与可见入口

```text
┌────────────────────────────┐
│ 便签标题               ⋯  │
│ 正文                       │
│ 一段正文，可换行……         │
│ ────────────────────────── │
│ 待办                       │
│ □ 待办项一                 │
│ ☑ 待办项二                 │
│                            │
│ ＋ 添加待办    ＋ 添加文字  │
└────────────────────────────┘
```

已确认**文字与待办可共存，并分成同一议程项的两个部分**：纯文字、纯待办、混合三种便签均成立，不设置互斥模式。正文区在前，待办区在后，以「正文」「待办」小标题和轻分隔明确区分，两区各自提供添加／编辑入口；仅支持一段可换行的纯文本，不提供 Markdown／富文本工具栏。

- 保留标题快速添加；新便签创建后两个添加按钮立即可见，无需先点整卡。
- 「＋ 添加待办」展开并聚焦输入行；Enter 保存并继续添加，Esc 取消当前草稿；中文组合输入不误提交。
- 「＋ 添加文字」显示正文编辑区；已有文字时入口变为「编辑文字」。使用明确的「保存／取消」，正文 Enter 换行，不用失焦静默保存。
- 正文为空后保存即清空文字；推荐最长 5000 字符、标题沿用 120 字符，上限在前后端一致校验。
- 默认展示正文摘要与前 3 个待办；超出时提供明确的「展开全部／收起」，而不是让整张卡承担隐含按钮语义。展开全部不截断正文。
- 允许多张便签同时展开；按钮、编辑框、复选框操作不触发卡片收起。
- 待办完成度仅计算子项；文字不计入分母。子项全完成不自动归档；纯文字便签也可手动移入已完成区。
- ⋯ 保留编辑标题、置顶、安排到某天、复制、标记已完成／恢复、删除；安排浮层与正文／待办分区保持一致的文案。
- 「复制一份」推荐复制正文与全部子项，保留勾选状态，生成新 ID，取消置顶／归档；当前实现只复制标题，本轮应修正便签复制语义。
- 删除确认说明正文及待办会一起删除。改名、编辑正文、置顶和归档不得相互覆盖字段。

### 3.4 视觉与动画

沿用宣纸底、墨色字和朱砂强调；便签可用暖黄纸面、轻描边、两层柔和阴影与细小顶部纸签作为识别。不随机旋转卡片，不用强装饰遮挡正文。

| 场景 | 推荐反馈 | 时长 |
| --- | --- | --- |
| 新建便签 | 透明度渐入，边线短暂强调 | 180–220ms |
| 悬停／键盘聚焦 | 纸面与阴影过渡，添加入口清晰 | 120–160ms |
| 展开正文／待办 | 复用高度测量式 Collapse + 内容淡入 | 180–220ms |
| 勾选待办 | 自绘勾线、文字颜色与划线过渡 | 120–180ms |
| 保存文字 | 短暂「已保存」状态 | 无循环动画 |
| 归档 | 退出淡化；成功后移动至已完成区 | 150–180ms |

保存失败保留草稿与错误提示，禁止先移除卡片再静默吞掉错误。遵守 `prefers-reduced-motion`，减少动态时取消高度过渡与入退场动画。继续兼容 macOS 11：不使用容器查询、`grid-template-rows` 过渡或导致浮层包含块改变的残留 transform；浮层 portal 到 body。

## 4. 日历日视图：日常安排与事件两栏

### 4.1 布局与时间轴

```text
                 当前日期（沿用日历标题栏）
时间刻度 │ 日常安排               │ 事件
全天     │ —                      │ 全天／跨日事件
08:30    │ ┌┄┄ 点击添加类别 ┄┄┐   │
09:00    │ │ ＋ 添加类别      │   │ 09:00–10:00 会议
10:00    │ └┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┘   │
10:15    │ ┌┄┄ 点击添加类别 ┄┄┐   │
```

- 平行的两列：左列「日常安排」呈现日常事务，右列「事件」呈现临时事件；在当前时间轴内容区内各占 50%（不含时间刻度、内部日历栏及外部倒计时栏）。两栏标题固定，单一垂直滚动容器与一根共享时间轴，避免两栏滚动错位。
- 时间轴保留 00:00–24:00，初次进入滚到 08:00 附近；切日期保留滚动位置，只有显式“今天”等操作需要定位时才重设。
- 高度与位置沿用 `hourHeight(fontSize)` 的同源像素计算，四档字号下两栏严格对齐。
- 右栏承接原日视图全天／跨日区与定时事件；全天区只在右侧填内容，左侧留同高占位，时间零点必须对齐。
- 事件之间仍按泳道并排；日常安排不参与事件泳道、不改变事件宽度算法。
- 保留内部迷你月历 rail，维持现有宽度及字号适配规则；日历页面外部倒计时栏与周视图 rail 同样保留。不通过移除日历、扩大主区或增大窗口最小宽度来容纳双栏。
- 双栏容器沿用当前时间轴区域宽度，按剩余可用宽度等分，随窗口连续伸缩；两列轨道使用可收缩约束，内部文字换行或省略，不得被内容最小宽撑破。保持左右布局，不退为上下排列，不用固定最小列宽引入新的横向滚动。
- 检查外部倒计时栏、内部月历、日期标题、工具按钮、全天区、时间刻度、双栏卡片、类别浮层与抽屉的尺寸联动。长类别、长事件标题及多事件泳道下仍须保持可操作；完整文字通过展开或提示可读。

### 4.2 默认四个空时间块（确定需求）

| 稳定 slotKey | 时段 | 初始内容 |
| --- | --- | --- |
| morning_1 | 08:30–10:00 | 无类别，虚线框 |
| morning_2 | 10:15–12:00 | 无类别，虚线框 |
| afternoon | 14:30–16:30 | 无类别，虚线框 |
| evening | 19:00–20:30 | 无类别，虚线框 |

每天，包括周末与过去日期，默认显示四个虚框；不根据昨天的类别预填，不生成日历事件。虚框仅显示「＋ 添加类别」，不重复显示醒目的时间文字；其起点与高度按真实时段投影到共享时间轴，时段通过轴刻度、悬停提示及无障碍标签表达。虚框是可操作占位，不是已创建安排。

### 4.3 类别编辑

- 单击虚框打开站内轻浮层，提供「英语、实验、开发、文献、写作、课程」六个可点击类别。
- 保留自定义类别名称（建议 1–20 字符）；六项作为快捷建议而非提前给每天分配类别。类别字段使用文字而非封闭枚举，预设列表集中配置，未来增加类别无需改表或迁移已有安排。
- 一块只能有一个类别。选择后持久化，虚框切为柔和实色卡片；清空类别后恢复原时段虚框。
- 点击已填写时间块可改类别或清空；取消／Esc／遮罩关闭不修改数据；所有入口都有文字标签和键盘焦点。
- 类别文字始终可见，颜色只辅助识别；默认六类使用固定色映射，自定义类别使用中性纸色。
- 四个默认时段固定，不支持拖拽、改时间、加第五块或删除默认栏位。清空意味着恢复虚框，不是删掉栏位。
- 日期 A 填入「英语」不影响日期 B；重启后 A 保留，B 仍为空。只读浏览任意日期不应写入数据库。
- 右栏空白处双击继续新建事件；左栏操作只编辑日常安排，不唤起事件抽屉。

## 5. 数据与接口方案

### 5.1 议程正文

复用 `agenda_items.note`，启动时显示已有 note，不制造第二个正文源；不用新增内容类型字段。保存正文走明确的局部更新接口，或在统一 store 更新入口完整转发其余字段；优先局部更新以减少整条覆写丢数据。浏览器预览后端与 Rust 后端校验与行为必须一致。

### 5.2 日常时间块

推荐新表 `daily_routine_slots`：

| 字段 | 约束与用途 |
| --- | --- |
| date | 本地 YYYY-MM-DD，与日历日期语义一致 |
| slot_key | 四种稳定标识之一 |
| category | 非空类别文字；清空用删除记录表示 |
| created_at / updated_at | 与现有数据时间戳规范一致 |
| 主键 | `(date, slot_key)`，同一天同一块只能一条 |

固定时段由一份前端领域配置定义；后端校验合法 slotKey，不重复存储时段。默认虚框由日期与配置推导，**只有填写后的块入库**。清空删除该记录，重新填写按新记录处理。此模型不涉及事件表、重复事件规则或无限生成未来日期。

建议命令：按日期查询 `list_daily_routine_slots(date)`、保存 `save_daily_routine_slot(date, slotKey, category)`、清空 `clear_daily_routine_slot(date, slotKey)`。导出备份读取全表。日期必须合法且真实存在，类别 trim 后校验，非法 slotKey 拒绝；保存采用 upsert 保留已有 created_at。

Store 的当天加载必须处理快速切日期的旧响应覆盖问题；更新成功后刷新对应日期缓存，失败保留原内容及编辑草稿。

### 5.3 升级与备份

- 新表存在性检查与迁移遵循已有幂等模式；首次升级先导出**包含全部 v1.2 议程数据**的 version 3 备份，再建表，备份失败应阻止迁移并报错。
- 新导出升 version 4，新增 `dailyRoutineSlots`；议程 note 与子项仍使用现有字段。
- 不修改老事件、倒计时、议程正文或归档状态；再次启动不重复备份，不插入任何默认日常记录。
- 旧版不支持新增日常数据；回退前保留新版数据库与备份。项目尚无 JSON 恢复能力，不宣称 v4 备份已可直接导入。

## 7. 验收与验证计划

### 7.1 议程

- 正常窗口两列、窄内容区单列，阅读顺序正确；置顶、复制、归档与恢复不丢正文／子项。
- 纯文字、纯清单、混合便签都能保存并在重启后还原；旧 note 自动显示，正文与待办是清晰的两个部分。
- 议程不显示七天事件预览；「安排到某天」仍可使用，生成事件包含正文与未完成待办，事务成功后归档，失败保留原事项。
- 首次创建后添加入口立即可见；不靠双击或隐藏菜单才能添加待办、编辑文字。
- 连续 Enter、IME、Esc、空输入、正文换行、取消、保存失败、删便签级联都符合约定。
- 多卡展开互不关闭；操作待办不影响展开状态；减少动态设置生效。
- 不改变倒计时的 Checklist 样式与里程碑交互；共用组件新增配置应有默认兼容行为。

### 7.2 日视图

- 四个时段与需求逐分一致，固定不可修改；初始都是空类别虚框，块内不突出时段文字，块的起止与时间轴逐分对齐；浏览十个日期不会产生四十条空记录。
- 同时段日常与事件并排且不覆盖；右栏同时发生的多个事件仍能编辑。
- 今天、过去、未来、周末分别填类别；切日与重启数据隔离；快速连续切日期无串日。
- 改类别不建事件，清空恢复虚框；右栏增删改事件不改变左栏。
- 全天、跨日与定时事件及当前时刻线保持对齐；滚动和字号切换后两栏仍使用同一刻度。
- 月／周视图不混入日常时间块；周视图既有布局保持可用。

### 7.3 数据与构建

- 纯逻辑：四个 slotKey／时段、默认合成与覆盖、类别校验及本地日期语义。
- DOM：入口可发现性、正文编辑、完整复制、日期切换竞态、虚框到填充／清空、双栏事件操作。
- Rust：唯一键／upsert／清空、非法日期／类别／slotKey、迁移备份数据完整、幂等、v4 导出。
- 执行 `pnpm check`、`cargo test --manifest-path src-tauri/Cargo.toml`、`pnpm build`；最终 `pnpm tauri build --debug` 后真机验收。
- 真机矩阵：1040／1240／1440px 窗宽 × 700／840／1000px 窗高 × 四档字号，普通／紧凑密度；检查裁字、焦点、浮层位置、动画、纸感与时间轴对齐。
- 动态缩放验收：连续拖动窗口边缘／四角、先缩后放、最大化再还原；分别在正文编辑、便签展开、时间轴滚动和类别浮层打开时操作。不得出现组件溢出、列宽失衡、按钮消失、浮层脱离锚点或两栏时间块错位。
- 保留内部日历的现有宽度规则，双栏占用原时间轴内容宽度并始终等分；极长文字及右栏多事件同时出现时不改变整体布局。
